# 宣言

加速器越来越快，CPU 侧的内核启动开销成为瓶颈——内核启动速度跟不上，GPU 就喂不饱。CUDA graph 在 GB200 上已是必需，这也是所有硬件的发展方向。

GraphTrainer 之所以存在，是因为大规模分布式训练终将需要编译器。问题只是时间早晚。它把完整训练步骤——前向、损失、反向（以及可选的 optimizer.step）——捕获为单个 FX 图，再在执行前对图做变换和优化。它作为 torchtitan 之上的实验项目，既是编译器驱动训练的试验场，也演示了如何把 PyTorch 编译器当作工具箱使用。

## Eager 模式的挑战

**可组合性很脆弱。** 让 FSDP2、激活检查点、torch.compile 和 CUDA graph 协同工作如同排雷。每个特性都是独立系统，各有拦截点，彼此以不明显的方式互相干扰：compile 在 FSDP2 上产生图断裂，AC 在反向重算 FSDP2 的 all-gather，AC 配合 compile 的图断裂会使 AC 失效并导致 OOM，等等。每种组合都需要单独的绕过方案，而针对一对组合的绕过方案可能破坏另一对。

**CUDA graph 很难。** 在 eager 下让 CUDA graph 工作，需要深入理解 PyTorch autograd 引擎内部机制并谨慎管理内存。包裹完整训练步骤尚可处理；区域化 CUDA graph 则难得多。

**调度粒度粗。** 在 eager 下，`autograd.Function` 和 Hook 是细粒度调度的唯一机制，粒度不够——代码很快变得丑陋。MoE 的微批重叠就是一例。有了图表示，调度只是节点重排。

## GraphTrainer 押注的方向

**单一统一图。** 把整个训练步骤——前向、损失、反向（以及可选的 optimizer.step）——捕获为一张扁平的 FX 图。没有拼接的独立子图，没有不透明边界。每个操作都完全可见——尤其是所有反向计算都是显式的。

**每个优化都是一次图变换。** 激活检查点、CUDA graph、CPU offload、通信重叠、内核融合——全部表达为同一张图上的变换。变换天然可组合，因为它们共享同一表示。新增优化就是写一个新变换，而不是把 Hook 穿遍整个栈。

**SimpleFSDP。** 面向编译器的 FSDP2 替代方案，把 all-gather 和 reduce-scatter 表达为可追踪的 DTensor 操作。集合通信作为节点出现在图中，因此可被变换重排、融合和重叠——而不是藏在模块 Hook 背后。

**CUDA graph 变得可控。** 有了图，所有计算都是显式的——没有隐藏的 autograd 状态，没有不透明的内存管理。分段包裹 CUDA graph 很直接，因为你能清楚看到需要捕获什么。

**硬件异构性。** 大多数非 GPU 加速器——TPU、Trainium 等——都假定图的存在，并且有完整图可供优化时表现更好。

**自动研究。** 图是具体产物，智能体可以程序化地分析和变换——相比把行为分散在运行时 Hook 和 autograd 状态中的 eager 代码，它是更适合智能体优化的基底。

**可调试性。** 图可检查。你可以导出它、对比变换前后的差异，精确看到改了什么。出问题时，你读的是一个具体程序——而不是单步跟踪回调链。
